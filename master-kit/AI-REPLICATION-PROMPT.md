# 给 AI 的工作台复刻提示词

你正在基于 BadMark 可复用母版创建或维护一个本地图像工作台。先读取 `AGENTS.md`、`master-kit/README.md`、`package.json` 和现有测试，再检查 Git 状态。母版中的 `src/`、`server/`、`plugins/`、`scripts/` 和 `tests/` 是一套已经联通的正式实现。

必须保留以下工程行为：

1. 所有上传原件只读保存，派生图片使用新文件和新版本，任何重新生成、改款、白底或裂变都不能覆盖历史图片。
2. 创建任务时冻结趋势、素材、参考图、提示词和参数；排队后修改资料卡不能改变已创建任务。
3. 每个任务可独立开始、暂停、继续、结束、重试和卡住重启。一个任务失败或等待不能阻塞其他项目和趋势任务。
4. 已生成的单张图片立即发布到工作台和成片管理，后续图片仍在生成时也可编辑已发布图片。
5. 同一成片的改款、精修和白底任务互斥，其他成片与其他项目可并发执行。
6. 系列生成、爆款裂变和重新生成采用追加式结果，保留连续 LOOK 编号、原任务、版本叠图和来源关系。
7. UI、HTTP 与 MCP 使用同一份持久化状态和文件仓库。UI 必须能独立完成全部工作，对话入口只是等价操作方式。
8. 文件访问必须验证真实路径、来源和普通文件类型；拒绝路径穿越与目录外写入。结果必须来自当前任务的真实生成目录。
9. 归档可恢复；永久删除只能从归档状态触发。删除业务记录时仍保留原文件和历史任务快照。
10. 保留 v1 到当前状态的迁移、数据库备份、并发修订保护和服务重启恢复。

允许通过配置修改产品名称、品牌文案、素材类型、提示词模板、导航文字、插件 ID 和端口。修改任务状态机、数据结构、文件边界、MCP 合同或历史版本规则前，必须说明兼容方案并更新对应迁移和合同测试。

实现工作时遵守以下顺序：读取现状和测试，完成最小范围修改，更新相关测试，运行 `npm run check`，运行 `npm run master:package` 和 `npm run master:verify`，检查发布包不含 `.badmark`、`node_modules`、`dist`、生成图片、日志、凭据或开发电脑绝对路径，最后创建独立 Git commit。

禁止用静态 Demo、占位图、模拟完成状态或浏览器本地缓存代替现有真实链路。不要删除旧任务类型、旧数据迁移和 MCP/API 兼容入口。不要要求用户把 UI 中已经提交的任务提示词复制到另一个对话。
